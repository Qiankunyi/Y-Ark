# 保存与分组架构 · 0.2.0

GUI 构建在 ui.py，用户操作和主线程数据库写入在 app.py；后台 Worker 只通过结构化事件汇报。profiles.py 定义输出质量和容器，创建任务时写入 SQLite options_json，重启和重试从该任务读取。

下载引擎只负责获得原音视频和封面。视频先合并为工作文件，再按所选容器无重新编码封装。所有下载、本地音频转存、本地视频转存最终调用同一 finalize_media：检查轨道和时长、封装、嵌入封面、读回校验、检查容器及分辨率限制。交付随后由不覆盖的 deliver 完成。封面判断不再把任意 MKV 附件当封面，已有错误封面也会替换成这次的原 JPG。

core.py 管理历史和任务。旧 tasks 表增量添加 options_json，不修改旧成功状态；旧任务没有新选项时保留旧记录，新的格式选择只对新建任务生效。

monitor.py 的 channels 仍以频道 ID 唯一识别作者。creator_groups 与 creator_group_members 构成多对多分组关系；创建、重命名、删除和批量归属修改使用 SQLite 事务。删除分组只删分组及其关系。搜索与分组筛选共同得到作者 ID 范围，作品查询只针对这一范围，空范围不退回全体。

group_dialogs.py 实现管理和批量设置窗口。部分勾选表示混合归属，保留此状态不改变各作者原归属。UI 通过 QListWidget 和滚动区域显示大量作者，搜索后保留有效选择。

实际文件、设置、历史、分组和日志保存在本机，不引入服务器，不扫描最终收藏目录。封面内部校验与播放器/Windows 缩略图展示分别验收。
